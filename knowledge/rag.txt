Retrieval-Augmented Generation

Retrieval-augmented generation, or RAG, is a method that combines information retrieval with a language model. Its purpose is to help the model answer using a selected collection of documents instead of relying only on patterns learned during model training. A simple RAG system has two main periods: indexing and question answering.

During indexing, the system loads source documents and divides them into smaller pieces called chunks. Each chunk keeps metadata such as its source filename and position. An embedding model converts every chunk into a vector, which is an ordered list of numbers. Texts with related meanings should receive vectors that are close to one another in the embedding space. The application stores the chunks and their vectors in matching order.

During question answering, the same embedding model converts the user's question into another vector. The system compares this query vector with all stored chunk vectors. Cosine similarity is one common comparison method. It measures the angle between two vectors and produces a score that represents how similar their directions are. The chunks are ranked by score, and the highest-ranked results are called the Top-K chunks. If K is three, the system selects at most three chunks.

The selected chunks are combined into a context. Clear source labels are added so that the later answer can identify where information came from. The application builds a prompt containing instructions, the retrieved context, and the user's question. A generation model then produces an answer. A grounded prompt tells the model to use only the supplied context and to admit when the context does not contain enough information.

Chunk size affects retrieval quality. A very large chunk can mix several topics, while a very small chunk can lose necessary explanation. Overlap repeats a small number of words between neighboring chunks so that an idea near a boundary is less likely to be separated from its supporting details. More overlap also creates more stored text and more vectors, so it should remain moderate.

RAG does not guarantee truth. Retrieval may select an irrelevant chunk, a source document may be wrong, or the language model may ignore instructions. Debug output, source citations, test questions, and an explicit insufficient-information response make these failures easier to observe. In this lab, each stage is implemented directly so that its effect can be inspected.
